# LAB4 — публикация в GitHub с двухкоммитной привязкой отчёта

Патч №07 (поверх патча №06). Работает только с исходным Git-клоном проекта:
`C:\Users\shata\Desktop\make-moons-mlops-labs`.

## Запуск

1. Перенести содержимое папки `make-moons-mlops-labs` из патча №06 в существующий проект с объединением.
2. Взять `07_PUBLISH_LAB4.ps1` из корня архива и положить в `Загрузки`.
3. Из `Загрузок` выполнить в PowerShell (можно обычным пользователем):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\07_PUBLISH_LAB4.ps1"
```

Скрипт использует явный путь `C:\Users\shata\Desktop\make-moons-mlops-labs` и не зависит от текущей папки консоли. Запуск от администратора **не обязателен** и иногда создаёт проблемы с правами файлов.

Сначала проверить без отправки в GitHub можно флагом `-NoPush` — это **не сухой прогон**: он создаст два локальных коммита, но не отправит их. Поэтому обычно предпочтителен один штатный запуск без этого флага.

## Что делает скрипт

1. Проверяет Git-клон, адрес `origin`, текущую ветку `main`, отсутствие подготовленных пользователем файлов в индексе и отсутствие занятой ветки `lab4`.
2. Сверяет историю `main` и `origin/main`. При равенстве или доказанном отставании локального `main` (является предком `origin/main`) продолжает работу, не меняя `main`. При расхождении историй или неопубликованных коммитах локального `main` безопасно останавливается. Проверяет отсутствие удалённой ветки `lab4`.
3. Сверяет **28 исходных CSV** и модель `LAB2/ml_model.joblib` по SHA-256/размеру с зафиксированным снимком `LAB4/data_integrity_baseline.json`.
4. Создаёт ветку `lab4`, добавляет только файлы ЛР4, общие зависимости, правила переноса строк и неизменённые входные CSV. Проверяет байты в индексе Git.
5. Создаёт первый коммит исходников (`feat(lab4)`). Запоминает его 40-символьный SHA.
6. Вызывает `LAB4/RUN_LAB4.ps1 -SkipInstall` для реального MLflow, повторных экспериментов и `pytest`, регенерируя `reports/LAB4` **после коммита кода**.
7. Проверяет, что хеши исходников на диске, в `source_manifest.json` и в первом Git-коммите совпадают; метрики и повторы положительны, MLflow Run IDs не заглушки.
8. Создаёт второй коммит (`docs(lab4)`) с `reports/LAB4` (включая обязательные четыре артефакта).
9. Снова проверяет отчёт, затем выполняет `git push -u origin lab4` **без `--force`**.

GitHub Actions запускается на коммите отчёта и проверяет неизменность исходных CSV, код/отчёт, полный эксперимент и тесты в Linux.
**Зелёный CI нельзя подтвердить до фактической публикации.** Проверить: <https://github.com/dozyanka/make-moons-mlops-labs/actions>.

## Гарантии и ограничения

- Каталоги `mlruns/1`, `mlruns/2`, `mlruns/3`, `mlflow.db` **не удаляются и не включаются в Git**.
- Старые отчёты ЛР1–3 и сохранённые обученные модели не пересоздаются.
- Правила `.gitattributes` фиксируют **исходные CSV с CRLF как есть**. У преподавателя при скачивании ветки будут те же SHA-256, что в исходном Windows-снимке и `reports/LAB1/hash_manifest.json`.
- Повторный запуск у преподавателя создаёт новые MLflow ID и время/память могут отличаться. Данные, алгоритм, пороги и ключевые метрики воспроизводимы.
- Чек-лист защиты, скринкаст, рецензия БЯМ и критический комментарий остаются ручными этапами приёмки.
- Если первый коммит прошёл, но дальнейший шаг завершился ошибкой, `main` остаётся прежней, `git push` не вызывается. Не удаляйте файлы и не делайте `git reset --hard`; присылайте текст ошибки для возобновления.
- Если локальные данные изменены по сравнению с архивом рабочего стола, скрипт остановится и объяснит конфликт до коммитов.

## Отличие патча №07 от №06: разные SHA main

Если `local main` старше `origin/main` и является его предком, **это не ошибка** при создании отдельной feature-ветки. Публикация от локального снимка проходит штатно, без `git pull`, `git reset --hard`, `git stash` и `force push`. GitHub `main` останется нетронутым.

При этом ветка `lab4` может не включать более свежие коммиты `main`. Перед объединением через Pull Request следует проверить отсутствие конфликтов и зелёный CI. Если ветки разошлись, скрипт останавливается до создания ветки: ручная проверка важнее автоматического слияния старого проекта.
