# Патч №09 — исправление Git-индекса CSV перед публикацией ЛР4

## Ситуация

После патча №08 рабочие файлы прошли проверку SHA-256, но сравнение с Git-индексом остановилось на `data/chunks/train_chunk_000.csv`. В индексе оказался blob с другими байтами (например, из-за нормализации CRLF/LF при предыдущем `git add`).

## Исправление

Скрипт `09_RESUME_LAB4_PUBLISH.ps1` продолжает работу в уже существующей ветке `lab4` **до первого коммита**. Для 28 CSV и модели ЛР2 скрипт:

1. Проверяет контрольные хеши и размеры файлов в рабочей папке.
2. Проверяет, что Git-атрибут `text` установлен в `unset` (директивой `-text`).
3. Через `git hash-object -w --no-filters` получает Git blob **из исходных байтов**, без нормализации.
4. При несовпадении обновляет **только индекс** командой `git update-index --add --cacheinfo`; содержимое CSV на диске остаётся нетронутым.
5. Проверяет все исходные файлы через `scripts/verify_lab4_data.py --check-git-index` и исходники для будущего `source_manifest.json`.
6. Только после этого запускает прежний защищённый сценарий: коммит кода, полный запуск ЛР4, проверка повторов и тестов, коммит отчётов и отправка ветки.

## Как пользоваться

- Архив распаковать с объединением папки `make-moons-mlops-labs` на рабочем столе. Он добавляет только этот файл с пояснением.
- Отдельный `09_RESUME_LAB4_PUBLISH.ps1` положить в `Загрузки`.
- Запустить обычный PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\09_RESUME_LAB4_PUBLISH.ps1"
```

Старые скрипты 06–08 повторно не запускать. Не выполнять `git reset --hard`, `git clean`, `git rm` и не удалять каталог `mlruns`.

### Границы проверки

Скрипт рассчитан на **текущее состояние**: ветка `lab4` уже существует, `HEAD` совпадает с локальным `main`, первый коммит ЛР4 ещё не создан, файлы патчей 06–08 установлены. Если состояние другое — сценарий останавливается. Он не делает `force push`, не обновляет `main` и не объединяет Git-истории автоматически.
