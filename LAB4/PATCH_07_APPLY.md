# Патч №07: безопасная публикация ЛР №4 при отставшем main

Условие предыдущего скрипта №06 «локальный main == origin/main» было избыточным. Этот патч обновляет **только сценарий публикации и его инструкцию**; модели, данные, отчёты, MLflow и тесты не изменяются.

## Установка

1. Перетащить `make-moons-mlops-labs` из архива в одноимённую папку на рабочем столе, подтвердить объединение.
2. Сохранить отдельный файл `07_PUBLISH_LAB4.ps1` в `C:\Users\shata\Downloads`.
3. Запустить PowerShell от обычного пользователя:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\07_PUBLISH_LAB4.ps1"
```

## Политика истории Git

- `local main == origin/main`: обычная публикация.
- `local main` является **предком** `origin/main`: скрипт сообщает отставание и публикует отдельную ветку `lab4` от локального `main`. Ни одна `main` не меняется.
- `local main` впереди `origin/main` или истории разошлись: остановка без коммитов.
- Если существует ветка `lab4`: остановка, без перезаписи истории.

Сценарий по-прежнему: контроль SHA-256 входов, два коммита (код и отчёт), MLflow, повторы, pytest, GitHub Actions. Статус Actions проверяется после публикации.

**Безопасность:** не запускайте для «исправления» `git reset --hard`, `git pull --rebase`, `git push --force`; не удаляйте `mlruns`. Система обязана явно подтвердить отношение веток через `git merge-base --is-ancestor`.
