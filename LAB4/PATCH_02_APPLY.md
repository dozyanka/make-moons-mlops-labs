# Патч №02 — совместимость MLflow 3.16+ и замечания преподавателя

**Назначение:** исправить сбой `mlflow.exceptions.MlflowException: The filesystem
tracking backend ... is in maintenance mode` после установки патча №01.

## Установка

1. Сохранить `02_LAB4_MLflow_Compatibility_Patch.zip` в «Загрузки».
2. Открыть архив, извлечь находящуюся внутри папку `make-moons-mlops-labs`
   **на рабочий стол**, согласиться на объединение и замену совпадающих файлов.
   **Не удалять** существующий проект `C:\Users\shata\Desktop\make-moons-mlops-labs`.
3. Запустить `LAB4\RUN_LAB4.cmd` снова. Все старые данные и обученная
   модель ЛР №2 остаются без изменений. Переустановка пакетов не требуется,
   но запускной скрипт сам проверит их наличие.
4. После успешного запуска открыть `reports/LAB4/validator_metrics.csv`: в обоих
   рядах `tracking_backend` должно быть `mlflow`, а `run_id` — реальные идентификаторы.
   Затем открыть `reports/LAB4/lab4_report.md`, показать отрицательные контроли
   и запустить `LAB4\OPEN_MLFLOW_UI.cmd` для просмотра MLflow.

**Вместо переноса архива**, для однократной проверки уже сейчас можно в
PowerShell из корня проекта выполнить:

```powershell
$env:MLFLOW_ALLOW_FILE_STORE = 'true'
.\.venv\Scripts\python.exe scripts\run_lab4.py
```

Это только временная команда: патч обеспечивает постоянное исправление.

## Состав патча

- `scripts/run_lab4.py`: явно разрешает курсом требуемый файловый backend
  MLflow перед созданием прогона; работает и при прямом запуске Python.
- `LAB4/RUN_LAB4.ps1`: та же настройка в PowerShell в текущем процессе.
- `LAB4/OPEN_MLFLOW_UI.cmd`: отдельный запуск MLflow UI с той же настройкой.
- `LAB4/README.md`: инструкция преподавателю.
- `.github/workflows/lab4-ci.yml`: совместимость в CI и дополнительные тесты.
- `tests/test_lab4_mlflow_tracking.py`: контрактная проверка флага до
  вызовов MLflow и проверка реальных run_id при установленном MLflow.
- `LAB4/LECTURE_NOTES_CHECK.md`: сверка заметок лекции с текущей ЛР.

**В архив не включены:** `data`, `mlruns`, `reports/LAB1-3`,
`reports/LAB4`, модели/чекпоинты и код ЛР5–8. Не выполняет Git-команды.

## Проверка и ограничения

В Linux-среде проверяется совместимость через изолированный подставной MLflow,
pytest и синтаксис запуска. Запуск под Windows и реальный MLflow 3.16
должны быть подтверждены твоим повторным запуском. Результаты до него
не считаем полными — реальных run_id пока нет.
