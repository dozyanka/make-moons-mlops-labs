# Запуск лабораторных работ на ПК

На Windows запустите двойным щелчком:

```text
DEMO\RUN.cmd
```

Также в корне репозитория есть:

```text
RUN_DEMO.cmd
```

Оба варианта открывают одно и то же меню.

## Что делает launcher

При первом запуске launcher:

1. ищет Python 3.11+;
2. если Python не найден и доступен `winget`, пытается установить Python 3.13;
3. создаёт локальное `.venv`;
4. устанавливает зависимости из `pyproject.toml`;
5. проверяет NumPy, pandas, scikit-learn, PyTorch, MLflow, pytest и остальные необходимые библиотеки;
6. открывает меню запуска лабораторных.

Старое виртуальное окружение переносить с другого компьютера не требуется.

## Меню (ЛР1–ЛР4)

| № | Действие | Результат |
|---|---|---|
| 1 | Проверить окружение | Python, PyTorch, MLflow и другие библиотеки |
| 2–4 | Запустить ЛР1, ЛР2 или ЛР3 | Независимое воспроизведение старых работ |
| 5 | Выполнить ЛР1–ЛР3 по очереди | Три воспроизведения |
| 6 | Быстрая демонстрация сохранённых моделей | Примеры ЛР1–ЛР4 (`defense_demo/run_all.py`) |
| 7 | Запустить тесты ЛР1–ЛР3 | pytest по исходным работам |
| 8 | Открыть MLflow ЛР1–ЛР3 | SQLite backend, локальный порт **5000** |
| 9 | Открыть отчёты | `reports/` и `demo_output/` |
| **10** | **Воспроизвести ЛР4 полностью** | Full, 24 chunks, MLflow, независимые повторы, pytest и coverage |
| **11** | **Быстрая демонстрация ЛР4** | 5 входов: нормальный, сдвиг, выброс, переворот метки, неверный тип |
| **12** | **Открыть MLflow ЛР4** | Файловый backend `mlruns/`, обычно порт **5001** |
| **13** | **Открыть отчёт ЛР4** | `reports/LAB4/lab4_report.md` |
| 0 | Выход | Закрыть меню |

При занятом порте **5001** меню выберет свободный порт и покажет его адрес. Используется `127.0.0.1`, интерфейс доступен только на компьютере проверяющего. `mlruns/` намеренно не хранится в Git; новые прогоны регистрируются при воспроизведении.


## Оригинальные и воспроизведённые результаты

Для ЛР №4 оригинальные результаты находятся в `reports\LAB4`, а воспроизведённые – в `demo_output\LAB4`. После запуска через DEMO исходный каталог восстанавливается даже при ошибке.

Результаты, полученные автором и отправленные на проверку:

```text
reports\LAB1
reports\LAB2
reports\LAB3
```

Launcher их не перезаписывает.

Новый запуск на компьютере проверяющего сохраняется отдельно:

```text
demo_output\LAB1
demo_output\LAB2
demo_output\LAB3
demo_output\logs
```

Папка `demo_output` не хранится в Git.

## Быстрая демонстрация и полный прогон

Быстрая демонстрация сохранённых моделей:

```text
DEMO\RUN.cmd
→ пункт 6
```

Полное воспроизведение ЛР1–ЛР3:

```text
DEMO\RUN.cmd
→ пункт 5
```

## GPU

GPU не требуется для запуска ЛР1–ЛР3.

ЛР3 может выполняться на CPU. Ранее выполненная проверка совпадения CPU/GPU сохранена в:

```text
reports\LAB3\device_parity.csv
```

Если на компьютере доступен CUDA-ускоритель, его наличие будет показано при проверке окружения.

## MLflow

Для ЛР №4 пункт **12** запускает отдельный локальный MLflow с backend `mlruns/` (обычно порт **5001**). ЛР №1–3 продолжают использовать SQLite и пункт 8.

После выполнения ЛР2 или ЛР3 MLflow UI можно открыть через пункт 8 меню.

Адрес:

```text
http://127.0.0.1:5000
```

Локальная база `mlflow.db` является runtime-файлом и не хранится в Git.

## Примечание по ЛР1

Официальные логи негативных pre-commit проверок уже сохранены в `reports\LAB1`.

Launcher не создаёт тестовые коммиты в репозитории проверяющего. При обычном воспроизведении выполняются безопасные проверки кода и тесты.

## ЛР4

Пункты **10–13** запускают ту же реализацию валидатора, что и `LAB4/RUN_LAB4.cmd`. Пункт **10** повторяет полный сценарий с тестами, пункт **11** показывает пять входов, пункт **12** открывает MLflow ЛР №4, пункт **13** – отчёт.

При необходимости без меню:

```bat
LAB4\RUN_LAB4.cmd
```

Для показа только решений валидатора:

```powershell
.\.venv\Scripts\python.exe .\defense_demo\lab4_demo.py
```

Проверить наличие всех файлов демонстрации **без обучения**:

```powershell
.\.venv\Scripts\python.exe .\DEMO\menu.py --lab4-smoke-test
```

GPU для ЛР4 не нужен. ЛР3 работает на CPU, если CUDA недоступна; ранее полученные результаты сохранены в `reports/LAB3/device_parity.csv`. Интерфейсы MLflow ЛР1–3 и ЛР4 используют **разные backend** и поэтому открываются отдельными пунктами меню.

Посмотрите текст консоли и `demo_output/logs/`. Официальные результаты при воспроизведении восстанавливаются автоматически. Если в Windows ограничены права на стандартную временную папку `pytest`, скрипт ЛР4 использует отдельный временный каталог, не требуя прав администратора.
