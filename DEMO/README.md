# DEMO: запуск ЛР1–ЛР4 на компьютере преподавателя

На Windows запустите **`RUN_DEMO.cmd`** из корня репозитория или **`DEMO\RUN.cmd`**. Права администратора не нужны. Запуск готовит локальное виртуальное окружение `.venv` и устанавливает зависимости, если это необходимо. Для ЛР4 используется существующая реализация `LAB4/RUN_LAB4.ps1`, а не её копия.

> Важно: для проверки ЛР4 нужен репозиторий из ветки **`lab4`**. В `main` пока сохранены предыдущие работы.

## Пункты меню

| № | Действие | Результат |
|---|---|---|
| 1 | Проверить окружение | Python, PyTorch, MLflow и другие библиотеки |
| 2–4 | Запустить ЛР1, ЛР2 или ЛР3 | Независимое воспроизведение старых работ |
| 5 | Выполнить ЛР1–ЛР3 по очереди | Три воспроизведения |
| 6 | Быстрая демонстрация сохранённых моделей | Примеры ЛР1–ЛР4 (`defense_demo/run_all.py`) |
| 7 | Запустить тесты ЛР1–ЛР3 | pytest по исходным работам |
| 8 | Открыть MLflow ЛР1–ЛР3 | SQLite backend, локальный порт **5000** |
| 9 | Открыть отчёты | `reports/` и `demo_output/` |
| **10** | **Воспроизвести ЛР4 полностью** | Full, 24 chunks, MLflow, независимые повторы, pytest и coverage |
| **11** | **Быстрая демонстрация ЛР4** | 5 входов: нормальный, сдвиг, выброс, переворот метки, неверный тип |
| **12** | **Открыть MLflow ЛР4** | Файловый backend `mlruns/`, обычно порт **5001** |
| **13** | **Открыть отчёт ЛР4** | `reports/LAB4/lab4_report.md` |
| 0 | Выход | Закрыть меню |

При занятом порте **5001** меню выберет свободный порт и покажет его адрес. Используется `127.0.0.1`, интерфейс доступен только на компьютере проверяющего. `mlruns/` намеренно не хранится в Git; новые прогоны регистрируются при воспроизведении.

## Оригиналы не перезаписываются

При выборе пунктов **2–5 или 10** DEMO временно подменяет соответствующую папку `reports/LABn`, копирует результат в `demo_output/LABn`, затем восстанавливает оригинал **даже при ошибке прогона**. Для ЛР4 также сохраняются журналы в `demo_output/logs/LAB4_*.log`.

- Официальные отчёты: `reports/LAB1/`, `reports/LAB2/`, `reports/LAB3/`, `reports/LAB4/`.
- Воспроизведённые: `demo_output/LAB1/` … `demo_output/LAB4/`.
- Индекс артефактов: [`../reports/README.md`](../reports/README.md).

При запуске ЛР4 **не переобучаются** модели ЛР1–3 и не изменяются их датасеты. Для быстрой демонстрации №11 вообще не требуется повторное обучение: используется модель ЛР2 и сохранённый `validator_params.npz`.

## Отдельный запуск ЛР4

При необходимости без меню:

```bat
LAB4\RUN_LAB4.cmd
```

Для показа только решений валидатора:

```powershell
.\.venv\Scripts\python.exe .\defense_demo\lab4_demo.py
```

Проверить наличие всех файлов демонстрации **без обучения**:

```powershell
.\.venv\Scripts\python.exe .\DEMO\menu.py --lab4-smoke-test
```

## CPU/GPU и MLflow

GPU для ЛР4 не нужен. ЛР3 работает на CPU, если CUDA недоступна; ранее полученные результаты паритета сохранены в `reports/LAB3/device_parity.csv`. Интерфейсы MLflow ЛР1–3 и ЛР4 используют **разные backend** и поэтому открываются отдельными пунктами меню.

## Если возникает ошибка

Посмотрите текст консоли и `demo_output/logs/`. Официальные результаты при воспроизведении восстанавливаются автоматически. Если в Windows ограничены права на стандартную временную папку `pytest`, скрипт ЛР4 использует отдельный временный каталог, не требуя прав администратора.
