# make-moons-mlops-labs

**Вариант:** 09
**Данные:** `sklearn.datasets.make_moons`
**Основная проблема:** нелинейность классов

## Статус

Лабораторные работы 1, 2 и 3 завершены. Лабораторная работа 4 реализована, локальный повтор с MLflow выполняется через отдельный launcher.

В проекте реализованы:

- воспроизводимая генерация исходного набора данных;
- SHA-256 исходного CSV;
- разбиение train / validation / test;
- подготовка данных чанками;
- EDA и визуализация нелинейности;
- классический ML в режимах full и chunks;
- PyTorch-модель в режимах full и streaming;
- bootstrap-интервалы для метрик;
- измерение времени и памяти;
- MLflow;
- проверки воспроизводимости;
- негативные контроли;
- CPU/GPU parity;
- pytest;
- pre-commit проверки;
- GitHub Actions CI.

## Основные параметры данных

Для ЛР1-ЛР3 используется один воспроизводимый набор данных:

- `n_samples = 24000`
- `noise = 0.22`
- `seed = 42`
- train: 16800
- validation: 3600
- test: 3600
- train chunks: 24
- chunk size: 700

## ЛР2

Одна модель обучается в двух режимах:

- full dataset;
- chunks.

`StandardScaler -> RBFSampler -> SGDClassifier`

## Публикация ЛР4 (патч №06)

ЛР4 публикуется **в отдельной ветке `lab4`**, без перезаписи `main`.
`LAB4/PUBLISH_LAB4.ps1` создаёт два последовательных коммита: код с байтовыми CSV и затем результаты эксперимента, ссылающиеся на коммит кода.
Перед публикацией выполняются SHA-256 проверка всех 28 CSV и модели ЛР2, проверка Git-индекса, MLflow-эксперимент (Full/Chunks + 2 повтора), pytest и контроль отчётов.

CSV исходных данных сохраняются байт-в-байт через правила `.gitattributes` `-text`, чтобы `hash_manifest.json` ЛР1, опубликованный код и GitHub Actions видели одинаковый SHA-256. **Данные и модели ЛР1–3 не генерируются и не переобучаются.**

См. `LAB4/GIT_AND_REPORT.md`.
